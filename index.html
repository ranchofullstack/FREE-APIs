Project ko “portfolio-grade” kya banata hai

API call to sab karte hain

Recruiter ya interviewer ko yeh nahi dikhna chahiye ki tumne fetch() chalaya. Use dikhna chahiye ki tumne failure, scale aur security ke baare mein socha. Yeh 6 cheezein har project mein daalo:

01
States, sirf data nahi
Loading skeleton, error message, empty result, offline — happy path to sab bana lete hain.
02
Debounce + AbortController
Har keystroke pe request mat bhejo; purani request cancel karo. Yeh race condition fix hai.
03
Caching
Same data baar-baar mat mangao. Map, localStorage ya SWR — rate limit bhi bachta hai.
04
Secrets safe
Key frontend bundle mein nahi. Ek chhota serverless proxy banao (niche section hai).
05
Data normalization
API ka shape ≠ UI ka shape. Ek mapper layer likho jo response ko clean objects mein badle.
06
Deploy + README
Live link, demo GIF, architecture, trade-offs. Bina live link ke project exist hi nahi karta.

Open-Meteo

Project: Weather app + city search 🌦️

Keyless, fast aur CORS-friendly weather API. Forecast 16 din tak, historical data 1940 se, aur air quality bhi milti hai. Is project ki asli skill dependent requests hai: pehle city → coordinates, phir coordinates → forecast.

FREE LIMIT10k/day · 5k/hr · 600/min
TERMSNon-commercial + attribution
LEVELBeginner

TMDB

Gotchas

      
    
        
  • Attribution mandatory hai: TMDB logo + yeh notice — “This product uses the TMDB API but is not endorsed or certified by TMDB.” Logo tumhari apni branding se kam prominent rakhna.
    • 
        
  • Free use non-commercial ke liye hai. Paid product ya ads wala app banana ho to TMDB se commercial terms lene padenge.

    •

N+1 problemmemoizationPromise.all batchingrecursion / treesset intersectionpagination


      
Gotchas

      
    
        
  • List endpoint sirf name + url deta hai. Cards ke liye har Pokémon ki detail chahiye — yahi N+1 problem hai. Id URL se nikalo: url.split("/").filter(Boolean).pop().
    • 
        
  • Fair use rule: responses locally cache karo. Abuse karne wale IP ban ho sakte hain. Data immutable hai, to localStorage ya IndexedDB mein permanently cache kar do.
    • 
        
  • Names lowercase-hyphenated hain (mr-mime, ho-oh) — user input normalise karo.
    • 
        
  • 1000 requests ek saath mat bhejo — 20–30 ke batches mein Promise.all.
    • 
        
  • GraphQL endpoint (graphql.pokeapi.co/v1beta2) beta hai: sirf POST, 100 calls/hr per IP, aur kabhi bhi change ho sakta hai. Core feature uski dependency pe mat banao.
    • 
      


      
Interview mein bolna“List endpoint N+1 problem create karta hai, isliye detail calls ko batches mein Promise.all kiya aur memory + localStorage cache lagaya. Evolution chain recursive tree hai, to DFS se flatten kiya.”

  • NASA endpoints kabhi-kabhi 5xx dete hain — retry with backoff aur last good response cache rakho.
    •

GitHub API
Project: GitHub Profile Analyzer 🔥

    

    

      
Portfolio mein yeh sabse zyada chamakta hai kyunki recruiter apna ya kisi ka bhi username daal ke result dekh sakta hai. Ab tak ke saare concepts yahan milte hain: pagination, rate-limit handling, aur N+1 se bachna.

FREE LIMIT60/hr → 5,000/hr (token)

Concepts jo demonstrate honge

      
paginationrate-limit headersETag / 304N+1 avoidanceREST vs GraphQLreduce / aggregationURL state


      
Gotchas

      
    
        
  • N+1 trap: har repo ke liye /languages call karoge to 30 repos = 30 calls, aur unauthenticated 60/hr limit aadhi khatam. Repo list ka language field use karo (1 call), bytes-level breakdown sirf top 5 repos ke liye optional rakho.
    • 
        
  • Unauthenticated limit 60/hr per IP hai, token se 5,000/hr. Token frontend mein mat daalo — proxy ya serverless function use karo.
    • 
        
  • Rate limit hit hone par 403 (ya 429) aata hai. x-ratelimit-remaining aur x-ratelimit-reset headers padho.
    • 
        
  • Forks filter karo (!r.fork), warna chart doosron ke code se bhar jayega. language null bhi ho sakta hai.
    • 
        
  • Search API ki limit alag hai: 10/min unauthenticated, 30/min authenticated.
    • 
        
  • Conditional requests (If-None-Match + ETag) pe 304 response rate limit mein count nahi hota — repeat searches ke liye use karo.
    • 
        
  • GraphQL API public data ke liye bhi token maangti hai, isliye REST se shuru karo aur GraphQL ko stretch rakho.
    • 
      


      
Interview mein bolna“Per-repo /languages calls N+1 hote hain aur 60/hr limit mein nahi chalte. Isliye repo list ke language field se aggregate kiya, aur bytes-level breakdown sirf top 5 repos ke liye optional rakha.”

    

  


  
  

    
API key frontend mein mat chhodo
TMDB + NASA + GitHub token

    
VITE_ ya REACT_APP_ prefix wali env variable bhi final bundle mein chali jaati hai — DevTools → Network tab mein koi bhi dekh leta hai. Keyless APIs aur DEMO_KEY pe koi issue nahi, par TMDB token, NASA key aur GitHub token ke liye ek chhota serverless proxy banao. Yeh khud ek interview talking point hai.

    
    
    
      
  • Path allowlist rakho, warna koi bhi tumhare proxy se kuch bhi call kar sakta hai.
    • 
      
  • s-maxage caching se CDN repeat requests handle karta hai — tumhara rate limit bhi bachta hai.
    • 
      
  • .env ko .gitignore mein daalo. Key leak ho jaye to turant rotate karo.
    • 
      
  • Same pattern Vercel, Netlify Functions ya Cloudflare Workers pe chalta hai.
    •

Reality check
honest baat

  • Recruiters projects ke saath DSA, fundamentals, communication aur interview performance bhi dekhte hain.
    •

  • Jo bhi project daalo, uska har hissa khud explain kar pao. Interviewer kuch bhi puchh sakta hai.
    • 
        
  • Internships, referrals, open source aur consistent applying bhi utne hi important hain.
